\end{figure}

El diagrama es un modelo conceptual de responsabilidades, no una declaración de clases Python ni una copia de las tablas SQL. Representa la estructura estática del sistema, mostrando las principales entidades, sus atributos y las relaciones entre ellas. Se observa una jerarquía de herencia donde la clase \textit{Usuario} es la base para los actores \textit{Tutor} y \textit{Alumno}. Asimismo, se modelan los elementos centrales del sistema como \textit{Ejercicio}, \textit{Intento} y \textit{Resultado}, los cuales permiten gestionar el proceso de captura, análisis y retroalimentación de la escritura. Finalmente, se integran los módulos de procesamiento \textit{AnalisisOCR} y \textit{EvaluacionCLS}, responsables de la conversión de imágenes a texto y del cálculo del puntaje ortográfico mediante la secuencia correcta de letras, respectivamente. La clase \textit{Resultado} conserva las secuencias correctas obtenidas y posibles, la calificación y si el tutor ya confirmó el puntaje.

\subsection{Diagrama de secuencia del procesamiento de ejercicios}

Con el propósito de representar el comportamiento dinámico del sistema, en la Figura~\ref{fig:diagrama_secuencia} se presenta el diagrama de secuencia correspondiente al proceso de análisis de ejercicios, el cual describe la interacción entre los diferentes componentes involucrados desde la captura de la imagen hasta la generación de resultados.

\begin{figure}[H]
    \centering
    \resizebox{\textwidth}{!}{%
    \begin{sequencediagram}
        \def\unitfactor{0.9}
        \newinst{al}{:ALUMNO}
        \newinst[2.6]{fe}{:FRONTEND (React)}
        \newinst[0.9]{be}{:BACKEND (API)}
        \newinst[0.9]{ocr}{:MODULO\_OCR}
        \newinst[0.9]{cls}{:EVALUACION\_CLS}
        \newinst[0.9]{db}{:BASE\_DE\_DATOS}
        \begin{call}{al}{Subir\_imagen}{fe}{Entrega\_registrada}
            \begin{call}{fe}{Enviar\_imagen}{be}{Sugerencias\_guardadas}
                \begin{call}{be}{Procesar\_imagen}{ocr}{Texto\_extraído}
                \end{call}
                \begin{call}{be}{Calcular\_CLS}{cls}{CLS\_sugerido}
                \end{call}
                \begin{call}{be}{Guardar\_resultado}{db}{Confirmación}
                \end{call}
            \end{call}
        \end{call}
    \end{sequencediagram}}
    \caption{Diagrama de secuencia del procesamiento de ejercicios}
    \label{fig:diagrama_secuencia}
\end{figure}

El diagrama muestra cómo el alumno interactúa con la interfaz para enviar una imagen, la cual es procesada por el backend mediante un módulo OCR para la extracción de texto. Posteriormente, el módulo de evaluación ortográfica compara el texto con las respuestas aceptadas del ejercicio y calcula el puntaje CLS. Las sugerencias se almacenan en el JSON del intento y se confirma el registro al alumno. La revisión del tutor ocurre en una solicitud posterior: valida la imagen, guarda el CLS confirmado y habilita su incorporación al progreso. Si no hay texto o referencia, la entrega requiere revisión manual sin una puntuación automática confirmada.

Los servicios de cálculo se ejecutan en el contenedor del Back-End; no requieren un servidor de procesamiento separado.

El servicio \texttt{db-init} aplica el esquema y las migraciones antes de iniciar el Back-End. La configuración local puede utilizar SQL Server en un contenedor en lugar de Cloud SQL; ambas opciones mantienen el cálculo CLS dentro de la API. El diagrama describe los archivos de despliegue del proyecto y no constituye evidencia de disponibilidad de un entorno publicado.
